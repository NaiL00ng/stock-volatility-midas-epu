### 原因及对照证据

[XGBoost 2.0.3列抽样源码](https://github.com/dmlc/xgboost/blob/v2.0.3/src/common/random.cc)调用C++标准库的洗牌；[Microsoft STL 17.6实现](https://github.com/microsoft/STL/blob/vs-2022-17.6/stl/inc/algorithm)与本机macOS实现的抽样序列不同。诊断补丁保留mt19937引擎和种子，只切换列洗牌；没有按测试损失搜索随机种子或调参。兼容逻辑为顺序扩展的Fisher–Yates交换与拒绝取模整数映射。

同一份本地编译的2.0.3库关闭兼容开关后，CSI300首验证块最大差异恢复为0.874474，与官方macOS轮子一致；打开后变为0。由此可把这一对照中的差异定位到列抽样实现，而非笼统归结为“机器不同”。仅在macOS安装官方2.0.3，仍不能重现Windows抽样。

新增2.0.3、2.1.4、3.0.5及3.4.1的线程/树方法/截距控制检查共40组；1、2、4、8及默认线程在各自版本的首验证块中预测相同。2.0.3本地构建有4组原生与4组兼容对照，1.7.6兼容构建另有4组探针。1.7.6默认exact/固定初始截距没有匹配。见[平台探针](../results/verification/xgboost_platform_probes.csv)。没有穷举所有版本，不能声称唯一识别为2.0.3。

### DEC为什么仍不是精确复现

使用本次真正重训且完全匹配的XGBoost预测后，剩余差异全部发生在第二阶段。窗口/权重族及299/200规格选择划分一致，但形状参数由数值优化估计。更换到NumPy 1.26.4、pandas 2.1.4、SciPy 1.11.4、statsmodels 0.14.2后，最大差异依次为0.002686、0.00002918、0.003101，仍未精确匹配；这是旧数值栈探针，不能冒充恢复的原环境。

在当前数值栈中，原工作簿重建与CSV读回仅有极小输入舍入差异，第二阶段输出仍会变化。这证明当前估计存在数值敏感性，但不足以断言历史误差只由某一个库版本造成。[数值敏感性表](../results/verification/stage2_numerical_sensitivity.csv)保留实际比较。

代码用单起点L-BFGS-B最小化剖面OLS的SSE，且只依赖默认前向差分。SciPy文档明确区分[目标变化与投影梯度停止条件](https://docs.scipy.org/doc/scipy-1.11.4/reference/optimize.minimize-lbfgsb.html)。当前CSV输入检查的108次优化均报告成功，但6次用步长1e-4作独立有界差分复核后，投影梯度无穷范数仍大于0.001；最大约1.015。0.001是诊断筛查阈值，不是理论显著性标准。不能把`success=True`或某组权重解释为全局最优、严格收敛或稳定经济效应。

候选代码现已显式记录原默认停止参数，保存停止原因、梯度和迭代次数，对明显未达到驻点的结果发出警告，并暴露规格选择异常；未偷偷更换优化算法或用“更好”的新结果覆盖历史结果。加诊断后的完整公开运行与此前兼容试跑预测完全一致。[优化复核表](../results/verification/midas_optimizer_checks.csv)记录上述108次检查。原SciPy/BLAS、各重估点的模型和优化日志缺失，精确DEC仍未完成。

### 新发现的方法与数据问题

第二阶段验证残差不是简单500条全样本OLS：第一条无残差滞后，499条按时间分为299条估计、200条评分；只选一次窗口与权重族，测试期每60条保留行重估形状参数与线性系数。Beta原始权重先下截至1e-12再归一化。候选论文已补齐目标、参数起点、边界、停止规则及实际信息时序。

历史变换先计算下一行目标，再删除缺失特征。上证50源表含2018-06-18、与前行同收盘价且零成交量的记录；[上交所官方公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20171222_4438363.shtml)确认该日休市。其自身虽被特征缺失删除，2018-06-15的超前目标仍取人工零收益，滚动特征亦受影响。2018-06-25的残差滞后对应这一6月18日目标，并非当日已经实现的紧邻交易日预测误差。未发现这处处理使用未来残差，但残差间隔与公式的理想连续交易日解释不一致。

这是上证50历史实验的实际数据缺陷；“与存档输入匹配”只能确认来源，不能证明输入已正确。CSI300描述统计的零值插入位置与这个休市日相邻，是进一步的关联线索，但没有原始额外行，仍不能断言二者同源。其他市场的零成交量不因此一概视为休市。见[时序核对](../results/verification/method_timing_checks.csv)及[异常日期](../results/verification/method_timing_exceptions.csv)。

[时序检查脚本](../scripts/check_method_timing.py)另在本地generated中生成排除已确认休市行、从头构造的上证50输入，未修改原文件。新输入的条数和划分见[修正输入摘要](../results/verification/sse50_correction_summary.json)。已在同一数值环境中分别对原输入和修正输入重训全部四个模型，构成独立的新日历清洗试验，不替换历史指标。修正后建模3919条、测试1919条；共同1915个日期上，两组预测统一使用修正目标，避免把人工零收益继续作为评价真值。当前论文已明确标注历史缺陷，并在附录另列新试验。

## 已解决：描述统计的数值差异

现存CSI300行情共有3942条价格。按论文定义 `log(close_t / close_(t-1))` 计算，并删除首个不可定义值，正确得到3941条收益率。当前输入不存在重复日期、缺失OHLCV或非正收盘价。

在这3941条收益率的第2053个插入位置（Python从0计数），即2018-06-15与2018-06-19两条收益率之间，额外插入一个零值，可重构历史统计：10项描述统计、7个检验统计量及7个p值，合计24/24匹配。检索全部3942个插入位置后，仅这一位置的四个Ljung–Box统计量同时在1e-9以内匹配；下一最佳位置的最大差异约0.0671。

这一数值指纹强烈支持历史摘要来自额外插入该零值的序列；它不构成对所有可能历史序列的唯一性证明。没有保存额外记录的日期或产生它的操作日志，因此不能认定它是某个节假日、重复行或人为首行填充。插入零值只用于诊断，未用于正式统计或训练。

| 原先5项差异 | 历史表 | 当前正确口径 |

| 收益率条数 | 3942 | 3941 |
| 均值 | 0.000058380764 | 0.000058395578 |
| 样本标准差 | 0.013636900758 | 0.013638631188 |
| 偏度 | -0.5761996540 | -0.5761298845 |

另外三处分位数也随样本变化，已一并重算；原先的349项检查仅包含其中7项描述统计，不能把原先5项差异理解为全部差异。正态性、自相关和ARCH检验也已重算，原有关于厚尾与序列依赖的描述性结论不因这次修正改变。极小p值显示为0是数值下溢，不表示数学上精确为零。

论文已使用[修正统计及图件](../results/descriptive-corrected/)。[历史统计](../results/descriptive/)保留原字节与原像素用于追溯；[24项核对](../results/verification/descriptive_lineage.csv)逐项列出历史、正确值和额外零值重构值。同时修复上轮公开稿均值单元格被p值格式替换误伤的问题；本次直接按数值生成并核对表格。

## 新增日历清洗试验的实际结果

[同日期、同一修正目标比较](../results/verification/sse50_calendar_common_dates.csv)使用1915条。重新训练后，XGBoost的QLIKE由原输入重训的4.507373变为4.756812，DEC由3.528922变为3.672719；MSE分别由4.902582变为4.933710、4.931264变为4.962050。GARCH、DEC、HAR、XGBoost的QLIKE排序在本次对照中保持一致，但数值确有变化，不能把错误视为无影响。只有一条共同日期目标不同，预测变化还包含相邻特征、扩展训练样本与重估位置变化。
