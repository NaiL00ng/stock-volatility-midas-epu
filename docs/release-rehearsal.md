### 发现的问题与修正

1. **基础解释器命令不一定可用。** 本机`python3.12`不在PATH中，改用已安装解释器的完整路径创建venv；README和示例说明增加版本检查及完整路径用法。
2. **pip成功不代表原生库可加载。** 动态库检查发现XGBoost使用系统已有的Homebrew libomp；这是Python虚拟环境之外的前置依赖。本轮没有安装或修改系统Homebrew。说明已补充macOS的libomp准备方法，并把原生库导入检查加入快速开始步骤。[Homebrew官方libomp说明](https://formulae.brew.sh/formula/libomp)给出安装方式；[pip check官方说明](https://pip.pypa.io/en/stable/cli/pip_check/)只承诺检查已安装包的依赖兼容性。
3. **只固定直接依赖仍可能使安装组合变化。** requirements-demo.txt现在用`-c requirements-reproduction.txt`约束传递版本；约束不会主动安装完整研究环境。第二次全新安装验证了这一最终配置，没有增加不需要的研究依赖。
4. **首次运行提示。** 新环境会出现Matplotlib构建字体缓存的提示，已在输出说明中解释，避免把正常初始化当作错误。

## 演练边界

初轮复用已有依赖；本轮已补做两个全新Python环境的安装验证。基础Python解释器、macOS和系统已有OpenMP仍被使用，因此这不是一台完全空白计算机的操作系统安装测试。Linux和Windows未实际验证。requirements-demo.txt及其约束只验证最小示例所需的26项Python依赖，本轮没有在新环境安装或重跑完整真实数据研究流程；它们也不是历史训练环境的唯一还原。

合成示例没有重现GARCH、HAR或完整区间实验，也不验证EPU经济作用。普通XGBoost与历史兼容构建的区别、数据获取条件、真实发布日期、全新留出评估及未实现的文献基准仍按原限制披露。许可证和数据再分发权也未由此次演练设定。

初轮与本轮的备份、演练副本和日志分别保留在`generated/release-rehearsal/`与`generated/fresh-install-check/`，不列入上传清单。未来分发只按[逐项清单](upload-manifest.md)和[SHA256表](checksums.sha256)取文件，不能整包上传含环境和本地数据的父目录。
